# 微信小程序：代码包、静态资源与真机兼容

包体与真机这两块的事故都不在开发者工具里显现：一块是代码包超限，
一块是「工具里好好、真机白屏」。这份文档讲这两类坑。

## 代码包

主包上限 2MB。静态图是**直接进包**的，一张 1.2MB 的 PNG 就能吃掉半个包。

### 主包与分包

`pages.json` 里三个 tab 页在主包，五个非 tab 页各占一个分包：

| 分包                | 页面     |
| ------------------- | -------- |
| `pages/about`       | 关于     |
| `pages/my-spots`    | 我的钓点 |
| `pages/spot-create` | 新建钓点 |
| `pages/spot-detail` | 钓点详情 |
| `pages/spot-edit`   | 编辑钓点 |

**分包的 root 就是页面所在的目录**，所以 `path` 写 `index`，
页面 URL 跟分包前一模一样（`/pages/spot-detail/index`）——
`navigateTo` 的八处调用点一个字都不用改。

分成五个而不是一个，是为了不动 URL：五个页面分处五个目录，
没有共同的前缀（`pages` 这个前缀下面还有三个 tab 页，当根会跟主包撞）。
代价是跨分包共用的组件（`FormRow` / `PageNav` / `SnapSheet` 等）留在主包里。

### 组件与资源跨包

- **分包能引用主包的一切**：组件、JS 模块、`static/` 里的文件。
  编译产物里就是相对路径（`../../components/...`）与 `require('../../constants/...')`。
- **主包引用不了分包里的东西。** 所以 `optimization.subPackages: true`
  只搬那些「只有分包用得到」的组件；被 tab 页用到的组件一律留在主包。
- `static/` 整个目录在**主包**里。以 `/` 开头的绝对路径一律从主包根目录解析，
  所以分包页里写 `/static/markers/lake.png` 不用改。
- 微信的规则是「分包中不能使用**其他分包**中的资源」——
  同理，一个分包也不能引用另一个分包的文件。

### 静态资源

`src/static` 下的文件是代码包的一部分，会跟着每个用户下载。
产物由脚本生成，源图在 `scripts/assets/`，**产物不手改**：

| 源图                  | 产物                  | 去哪儿                                  | 为什么是这个格式                                  |
| --------------------- | --------------------- | --------------------------------------- | ------------------------------------------------- |
| `spots.png`（1.2MB）  | `spots.jpg`（158KB）  | **CDN**，不进代码包                     | 要进 canvas，海报路径上只认 jpg/png               |
| `logo.png`（76KB）    | `logo.webp`（15KB）   | **CDN**，不进代码包                     | 只在 `<image>` 里出现，不进 canvas；WebP 带 alpha |
| `wxacode.jpg`（51KB） | `wxacode.png`（44KB） | `src/pages/spot-detail/static/`（分包） | 彩色码，JPEG 会把边界糊了，糊了就扫不出来         |

跑 `pnpm assets` 重新生成。理由写在 `scripts/optimize-assets.py` 的注释里。

**占位插画和 logo 为什么搬去了 CDN**：`src/static` 里的东西跟着每个用户下载，
而这两张图各自只在一种场景里露面 —— 插画只在「这条钓点没有照片」时才出现，
logo 只在关于页顶部出现，绝大多数会话根本用不上。
158KB 和 15KB 放进 2MB 的主包里，等于让所有人替少数人下载。
产物现在出到 `scripts/assets/cdn/`（不进版本库），手动上传到
`VITE_CDN_BASE_URL` 下，代码里引的是那个地址
（`src/pages/spot-detail/constants.ts` 与 `src/pages/about/constants.ts`）。

⚠️ 代价是**多了一个域名依赖**：`cdn.kanocifer.chat` 必须配成
**downloadFile 合法域名**，否则 `<image>` 和海报的 `canvas.createImage()`
都拿不到这些图 —— 头图那块留一片空白底色，海报上那块封面画不出来，
关于页顶部的应用图标也是空的（`<image>` 拉不到图不报错，只是白）。

`canvas.createImage()` 那边有配套的一条：本地文件读成 base64 时，
data URI 的 mime 要跟真实格式对得上（`src/utils/canvasImage.ts` 的 `mimeOf`），
所以海报上用的图只能是 png/jpg。包内现在只剩小程序码走这条 base64 路，
占位插画已经是网络地址 —— 那是 `createImage()` 官方明确支持的那种 src。

### 构建产物里的杂物

macOS 的 `.DS_Store` 会被 uni 原样抄进代码包（构建读的是磁盘，不是 git）。
`pnpm build` 末尾跑 `scripts/clean-dist.mjs` 清掉。

## 真机兼容

### JS 引擎：两端不是一套

小程序的**逻辑层**，iOS 跑**系统级的 JavaScriptCore**，Android 跑**微信自己打包的 V8**。
两边的版本不在一条线上：iOS 的 JSC 跟着系统走，Android 的 V8 跟着**微信客户端**走。

所以 **ES2022 的内置方法（`Array.prototype.at` / `Object.hasOwn`）在这两端不是同一回事** ——
iOS 15.4+ 的 JSC 就有，Android 的 V8 可能还没有。

踩到的一处：marked v18 的分词器用 `.at(-1)` 取栈顶，**任何一段 markdown 都会走到**
（见 `src/components/MarkdownView/MarkdownView.vue`）。缺这个方法的引擎上，
每次渲染都抛 `TypeError: t.at is not a function`，AI 建议面板一片空白。

**为什么不能靠「基础库最低版本设置」解决**：后台那项筛掉的是**基础库太老**的用户，
而基础库决定的是「有哪些 wx API」—— 它管不到引擎里有没有 `Array.prototype.at`。
微信能通过 OTA 给老客户端推新基础库，但**推不动客户端二进制里的 V8**。
理论上可以改用「小程序最低可用版本设置」筛**客户端版本**，但那等于直接把这些用户
挡在门外 —— 为一个几行 polyfill 能解决的问题砍用户，不划算。

**补法**：`src/utils/polyfills.ts` 补齐用到的内置方法，`main.ts` 的模块顶层装上。
理由跟下面「Vue 3 兼容层」一样：这类问题只有真机才炸，而真机不一定有。

### Vue 3 兼容层

`main.ts` 里补了 `$set` / `$delete` 两个实例方法 —— Vue 3 删掉了它们，而 mp-html v2 还在用（`setContent` 里的 `this.$set(this, 'nodes', …)` 是它的主路径）。不补这一层，mp-html 第一次渲染就抛 `this.$set is not a function`，白屏。

补法是对的：Vue 3 的响应式基于 Proxy，给对象加新属性本来就能被追踪到，`$set` 退化成一次普通赋值即可，语义与 Vue 2 的实现一致。

### marked 里的 ES2018 正则：整包白屏的真凶（已修）

**这个坑是真的，安卓会整包白屏** —— 不是 markdown 局部失败，
是 `common/vendor.js` 解析失败、整个小程序起不来。真机日志：

```
SyntaxError: Invalid regular expression: /^((?![*_])[\s\p{P}\p{S}])/u:
Invalid property name in character class
```

**为什么开发者工具里看不出来**：微信开发者工具的「将 JS 代码编译成 ES5」用 babel 转换，
它覆盖 `??`、`?.` 这些常规语法，但**不覆盖正则的这两个冷门插件**。
工具用的是较新的 V8，真机用的是微信客户端自带的引擎 —— 两边不是一套。
同样的案例：[小程序真机白屏：一个正则表达式引发的兼容性问题](https://weiserv.com/blog/mini-program-white-screen-marked-downgrade/)。

marked 里有两类 ES2018 正则语法，都在**正则字面量**里，语法错误发生在**解析期** ——
引擎一碰到，整份脚本就加载不了：

| 特性             | 条数 | 长什么样                                | 引擎门槛             |
| ---------------- | ---- | --------------------------------------- | -------------------- |
| Unicode 属性转义 | 8    | `/[\p{L}\p{N}]/u`、`/[\p{P}\p{S}]/u` 等 | Chrome 64 / iOS 11.3 |
| 命名捕获组       | 2    | `/(?<a>`+)[^`]+\k<a>(?!`)/`             | Chrome 64 / iOS 11.3 |

**两条门槛是同一条线** —— 只修属性转义不修命名组，目标引擎照样解析失败，等于没修。

下面四条修法在本项目都不成立，别再试：

| 说法                                                         | 实际情况                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 打开 `transpile`，让 uni-app 把 node_modules 的 ESM 转成 CJS | `transpile` 是 uni-app **CLI（webpack，Vue 2）** 时代的选项，Vue 3 的 Vite 管线里没有这个开关（`node_modules/@dcloudio` 全量搜不到这个词）。而且 ESM 本来就不是问题：rollup 已经把 marked 的 ESM 打进 `common/vendor.js`，产物里没有残留 `import`/`export` |
| 换 UMD 版 `marked.min.js`                                    | `marked.umd.js` 里**同样的 10 条正则一条不少**。UMD 只换模块格式、不动正则，换过去还丢掉 tree-shaking，等于拿新问题换旧问题                                                                                                                                |
| 把 `build.target` 调低，让 esbuild 降级                      | esbuild 0.14.40 起对不支持的正则字面量是改写成 `new RegExp(...)`，**不是**把 `\p{L}` 展开成字符类。只是把解析期报错变成运行期报错，模块顶层照样炸                                                                                                          |
| 降级 marked 到旧版本                                         | 属性转义从 **v4 起**就一直带着（v4、v9、v12、v13、v14、v15、v16、v18 全部命中），没有干净的旧版本可退。而且退到 v2 会把 2022 年的 ReDoS 漏洞（CVE-2022-21680）一起带回来                                                                                   |

**修法**：`pnpm patch marked@18.1.1`，把这 10 条正则换成 ES2017 兼容写法
（patch 在 `patches/marked@18.1.1.patch`，记录在 `pnpm-workspace.yaml` 的 `patchedDependencies`）。

- 8 条属性转义 → 显式字符范围。覆盖 ASCII 字母数字 + 拉丁扩展 +
  希腊/西里尔/希伯来/阿拉伯/印度/泰语 + 假名/汉字/谚文/全角字母数字。
  **中文标点（U+3000–U+303F、U+FF00 段）不在字母数字类里**，
  所以「中文标点 + 粗体」的定界判断与 marked 原本行为一致 ——
  中文加粗正是 `MarkdownView.vue` 里单独打过补丁的地方，不能在这里改坏。
- 2 条命名捕获组 → 按反引号个数枚举（1/2/3 个），最长优先。

**改捕获组时踩过的坑**：原来的 `(?<a>…)` 是**捕获组**，换成 `(?:…)` 会让组数少一个，
而这些规则会被拼进大正则、别的规则按序号引用 `\1` `\2` —— 组数一变引用就整体错位，
表现为强调标记匹配到错误的位置（`**加粗**和*斜体*` 里的粗体不认了）。
**替换必须保持组数一致**，用 `((?:…))` 而不是 `(?:…)`。

23 条样例（中文加粗/斜体/标点/列表/表格/引用/代码/代码跨度/带代码的链接/emoji/全角）
渲染结果与原版**逐字相同**。

**为什么是 patch 而不是换库**：patch 只动这 10 条正则，别的什么都不碰；
换库要改 `MarkdownView.vue` 的调用方式，还丢掉六年的修复和那六个安全补丁。

**防回退**：`scripts/check-mp-compat.mjs` 在每次 `pnpm build` 后扫产物，
发现属性转义或命名捕获组就让构建失败。marked 升级导致 patch 失效时，它会当场报出来，
而不是等真机白屏再回头翻产物。

**还剩的依赖**：产物里的 `??`、`?.` 仍靠开发者工具的 babel 兜底
（uni-app 的 mp-weixin 产物默认保留现代语法）。那部分是主流语法，babel 一定覆盖；
正则插件才是例外，所以只有它炸过。

### 渲染特性有下限

WXSS 不保证支持新特性。不支持时那一条声明会被**直接丢掉** —— 不是报错，是静默失效：

| 特性                                    | 门槛                      | 不支持时的症状                                                   |
| --------------------------------------- | ------------------------- | ---------------------------------------------------------------- |
| `@property` 注册（`--fish-flow-angle`） | Safari 16.4 / Chromium 85 | 自定义属性只能离散插值，流光渐变每 3 秒「跳」一下而不是「转」    |
| flex `gap`                              | Safari 14.5 / Chromium 84 | 声明被丢掉，那一行元素贴在一起，间距全没                         |
| `inset: 0` 简写                         | Safari 14.1 / Chromium 87 | 声明被丢掉，`&::before` 那层发光没有定位锚点，光晕跑到错误的位置 |

受影响的组件：`FishingAnalysisSheet`（流光），以及全仓库用 `gap` 的列表。

**三条都能在代码里躲开，躲的写法是固定的：**

- **`gap` → 用 margin。** 元素之间靠 `margin-right` 撑开，别处留白用 `margin-left` 或
  父级的 `padding`。注意父级 `padding` + 子级 `margin` 在 flex 容器里不折叠，
  相加时要算总间距，别以为写了 margin 就没有 padding。
- **`inset: 0` → 四边分别写。** `top` / `right` / `bottom` / `left` 各写一遍。
  这条对**任何** `position: absolute` 都要守着，尤其是带 `z-index: -1` 的装饰层 ——
  定位锚点一丢，装饰层就不在它该在的位置上，而且不报错。
- **`@property` → 注册不了就退成两段关键帧。** 但要清楚代价：
  没注册的自定义属性只能离散插值，`conic-gradient` 的角度会「跳」而不是「转」。
  真要流畅旋转，得把渐变本身换成一个静态图 + `transform: rotate` 动画。

**为什么强调静默失效**：这三条都不会报错、不会构建失败、开发者工具里也不会标黄。
一眼看过去代码是对的，坏的是老机器上那台没人再复现的手机 ——
所以只能靠「写的时候就绕开」，不能靠「测出来再修」。

### WXSS 编译器认不出的选择器：整页空白

上面三条是**静默失效** —— 声明被丢掉，页面照常显示，只是少一处效果。
还有一条是**硬失败**：选择器里出现了 WXSS 编译器不认的语法，那一份 WXSS **编译不过**，
用它的那个页面直接白屏，模拟器上盖一句「Compile .wxss error」。

踩到的是**通配选择器**：

```scss
/* 编译失败：error at token `*` */
.head__meta > * {
  margin: 0 12rpx 12rpx 0;
}
```

**症状**：构建期一路绿灯（SCSS → WXSS 由 vite 编译，它认 `*`），
只有微信开发者工具的 WXSS 编译器不认。表现是那一页整块白掉，
而开发者工具的 console 里未必有对应的报错条目 —— 自动化工具还会因此连不上模拟器
（`getPageMetaByWebviewId` 拿不到页面），排查时很容易误判成「自动化坏了」。

**躲法**：别用 `*`。要给孩子节点加样式，给它一个自己的类。

```scss
.head__tag {
  margin: 0 12rpx 12rpx 0;
}
```

**顺带一条**：mp-weixin 里父组件的作用域标记落在**组件宿主节点**上，
落不到子组件内部的节点上 —— 在父组件的 scoped 样式里写 `.chip` 想给子组件的
内部元素加样式，在小程序端是不生效的。要给子组件内部的元素加样式，
在子组件里加，或者像 `SpotDetailHead` 那样在子组件外面套一层自己的 view。

**怎么验**：`wechatide compile_wxss --file-path <相对路径>.wxss` 单文件编译，
不依赖模拟器，也不依赖整包刷新 —— 改完样式跑一遍就知道过不过。

**另一条静默失效是层叠上下文**：带 `z-index: -1` 的装饰层，如果它的祖先里没有一个 `position: relative; z-index: 0` 的容器把它圈住，
它会一路掉到抽屉/卡片的底色层下面去，光晕看着就是「没有」。
这跟渲染特性无关，所有内核都一样坏 —— 但同样不报错。
`FishingAnalysisSheet` 的流光按钮就靠这一行撑着，
见该组件 `.analysis__actions` 里的注释。

反方向还有一条同源的坑：装饰层所在的祖先**自己带 `transform`** 时，
这个 `z-index: -1` 会被关在祖先的层叠上下文里，从「垫在背景之下」翻成「压在背景之上」。
见 `docs/mp-weixin-platform.md` 的「transform 会创建层叠上下文」。

**微信体检里的「UI 异常」条目只给现象、不给机型** —— 必须拿到体检报告详情链接，
或用多机型真机复现，才能定性。代码里能筛出的候选就是上面这三个。
