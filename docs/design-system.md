# 设计系统

渔碌的界面是一套**材质系统**，也是一套**动效系统**。两者都按 iOS 的做法来，但落在小程序的能力边界内 —— 这条边界（没有弹簧引擎、没有 `backdrop-filter` 保证、没有 `prefers-reduced-motion`）决定了下面每一条规则的形状。

这份文档写**规则与判据**：改什么、去哪改、怎么算改对了。真源在 `src/styles/tokens/`，图标在 `scripts/gen-icons.mjs`，文案在 `src/constants/about.ts` —— 文档只解释为什么，不复述数值。

## 怎么用

| 场景                                       | 入口                                                                                     |
| ------------------------------------------ | ---------------------------------------------------------------------------------------- |
| 调颜色、字阶、间距、圆角、阴影、曲线、时长 | `src/styles/tokens/`，改一处全项目生效                                                   |
| 加一张卡                                   | 抄 `_card.scss` 的 `fish-card` / `fish-card-head` / `fish-card-title` / `fish-card-meta` |
| 加页面                                     | 抄「页面骨架」一节的三段结构                                                             |
| 加交互                                     | 「反馈」「动效」「手势与浮层」三节，每个动作对应一个 mixin                               |
| 换图标                                     | 改 `scripts/gen-icons.mjs` 的清单 → `pnpm icons`                                         |
| 想知道某个平台坑为什么这么写               | `docs/mp-weixin-platform.md`                                                             |

改完自检：`pnpm type-check` 与 `pnpm lint` 退出码 0，再过一遍带「自检」清单的章节。

## 底线：四件事同时成立

这四条是整套观感的地基。任何一条破了，界面立刻显出「不是这个 App」。

| 底线           | 含义                                                                                      | 破了会怎样                     |
| -------------- | ----------------------------------------------------------------------------------------- | ------------------------------ |
| **材质分层**   | 页面底是 systemGroupedBackground 的浅灰，卡片是白面浮在上面。靠**面**分层，不靠描边和阴影 | 变成「一堆描边的盒子」         |
| **发丝分隔线** | iOS separator 是 0.33pt，`$fish-border` 用 1rpx 就是那个量级                              | 「重描边」，最刺眼的一处       |
| **字阶成组**   | 11 级固定字号，每级自带字重、字距、行高                                                   | 「Material 味」的来源          |
| **按下即反馈** | 可点的东西在**手指落下**那一帧就要有反应，不是抬手之后                                    | 界面「假」，延迟感直接毁掉手感 |

后面所有章节都是这四条的展开。

## 原则：Apple 八条在本项目怎么落地

| 原则     | 本项目的判据                                                           |
| -------- | ---------------------------------------------------------------------- |
| **目的** | 一个页面只回答一个问题。数据页给结论，我的页给身份与出口，关于页给应用 |
| **主控** | 浮层有把手、遮罩可点关、能拖能退；破坏性操作才确认                     |
| **责任** | 免责与协议是初稿不是法务稿，上线前必须过法务                           |
| **熟悉** | 浮层一律从底部来、回底部去；分段控件按下变暗不缩小                     |
| **灵活** | 同一套骨架适配多页多尺寸；字号用 rpx 固定，不随机型漂                  |
| **简洁** | 省掉次级标签和说明文字，让版式自己说话                                 |
| **工艺** | 每一个间距、字号、时长都是能解释的选择，不留随机值                     |
| **愉悦** | 愉悦是前七条的结果，不是额外贴上去的装饰                               |

## 令牌

全部在 `src/styles/tokens/`，一个文件一件事：`_color` 色值、`_type` 字阶、`_space` 间距、`_depth` 圆角与阴影、`_material` 材质、`_motion` 动效、`_layout` 页面版式、`_card` 卡片版式、`_platform` uni-app 内置变量。**改那里就是改全项目。**

`src/uni.scss` 是入口，**只有一行**：

```scss
@use '@/styles/tokens/_index.scss' as *;
```

uni-app 会把 `src/uni.scss` 的**原文**拼到每个 scss 编译单元前面（vite 的 `additionalData`），这是「每个组件都拿得到令牌」的机制，拆文件不能拆掉它。`uni.scss` 里**不能再有变量声明** —— 注入时 `@use` 会被顶到声明后面，sass 直接报「@use 必须在其他规则之前」。要加令牌，去 `styles/tokens/` 里加。

新增主题 = 加一个文件 + 在 `_index.scss` 里加一行 `@forward`。`@forward` 把成员透传出来，入口再 `as *` 摊平成全局名，所以组件里照旧写 `$fish-blue`、`@include fish-type(body)`，不用带前缀。

这是**编译期常量**而不是 CSS 变量：canvas 2d 不解析 `var()`，只认 rgb/hex（见 `TideChart` 注释）；小程序端也没有 MutationObserver 监听主题切换。主题在编译期定死。

**canvas 侧的硬编码色值要手工与 `_color.scss` 保持一致** —— `$fish-tide`、`$fish-temp` 就是给这件事留的锚点（原因与后果见 `docs/mp-weixin-platform.md` 的「canvas」一节）。

### 样式分三层：谁写的

`src/styles/` 按**「谁写的」**分三层，不按「哪一页用的」分：

| 层       | 目录         | 谁写                     | 里面是什么                                                           |
| -------- | ------------ | ------------------------ | -------------------------------------------------------------------- |
| 令牌     | `tokens/`    | 人手写，改一处全项目生效 | 色值、字阶、间距、材质、版式的 mixin                                 |
| 共用版式 | `shared/`    | 人手写                   | 跨页共用的整页版式（`spot-form.scss`：投稿页与编辑页填的是同一张表） |
| 生成物   | `generated/` | 脚本产出，**勿手改**     | `qweather-icons.css`（和风图标字形映射表）                           |

分层的判据是**能不能手改**：能手改的进 `tokens/` 或 `shared/`，跑脚本出来的进 `generated/`。产物跟手写文件混在一个目录里，是最容易出事的地方 —— 改了一手，回头又被脚本覆盖。

`generated/` 里的文件跑完脚本之后**还要再跑一次 `npx oxfmt`**：脚本吐的是紧凑单行，仓库里存的是格式化后的版本，不补这一步 `oxfmt --check` 会红。改脚本的输出路径要同时改 `scripts/subset-qweather-icons.py` 的 `OUT_CSS` 和引用它的那几处注释。

组件自己的样式留在组件的 `<style scoped>` 里，不进 `shared/` —— 只有**两个及以上页面共用**的版式才提上去。

### CSS 变量：Sass 不解析它的值

一组外观只改几个值时，用 CSS 自定义属性比给每组复制一份规则干净 —— 当前天气卡就是：
每组外观只给四个 `--weather-*` 赋值，底下的规则一律读 `var()`。

⚠️ **自定义属性的值按纯 CSS 解析，Sass 不解析里面的变量。**

```scss
--weather-ink: $fish-ink; // ❌ 产物里原样输出 $fish-ink，这个颜色直接失效
```

必须插值：

```scss
--weather-ink: #{$fish-ink}; // ✅
```

构建不报错、lint 不报错、类型检查也不报错 —— **只有产物里能看出来**。
这类问题一律到 `dist/build/mp-weixin` 的 wxss 里核对，别只看编译通过。

另外：**值可以放令牌层，规则不行。** 令牌层会被 `uni.scss` 拼到每个组件的样式前面，
所以像天气外观表这种「只有一张卡在用」的东西放在组件自己的 `<style scoped>` 里；
共享的原语（墨色、弱化字色、深色面上的白字）仍然取令牌。

### 卡片

卡片是最高频的重复单位：数据页与详情页上九张浮起来的面，外壳、标题行、标题、元信息各写一份就要改九处。四个 mixin 都在 `_card.scss`：

```scss
@include fish-card; // 卡片外壳：玻璃面 + 卡内留白
@include fish-card-head; // 标题行：标题在左、元信息在右
@include fish-card-title; // 标题字阶（默认 headline）
@include fish-card-meta; // 元信息字阶（默认 caption2）
```

卡内留白不收进 `_space.scss`：那一份只管「页面里几个区块如何分开」，卡内留白是卡片自己的解剖结构，收进去就得连组件内部的间距一起管，改到最后谁也说不清一个数是谁的。

## 材质与深度

**圆角是轮廓，阴影是厚度。** 玻璃面的「外壳」就是这两样，材质本身（半透明底色 + 顶边高光）在 `_material.scss`。这两个总是成对出现：只调圆角不调阴影，面就贴在底上；只调阴影不调圆角，厚是厚了，但读起来是个方块。

```scss
@include fish-glass; // 玻璃卡：半透明底 + 顶边高光 + 多层阴影
@include fish-glass-blur; // 只给「底下有内容在动」的面
```

### 层次靠面，不靠描边

页面底是浅灰 grouped 背景，卡片是白面浮在上面 —— 这是 Apple 的 inset-grouped 结构。**不要用描边把两块区域隔开**：描边一多，界面立刻从「系统」滑向「后台管理系统」。

分隔线例外，而且必须是**发丝级**：`$fish-border` 是 1rpx。用 2rpx 的话，在 375pt 机型上正好 1pt，是 iOS 发丝线的三倍厚 —— 这是整套观感里最刺眼的一处。

### 模糊是增强，不是依赖

`fish-glass` 刻意**不写** `backdrop-filter`：

- 静态卡片背后是平滑渐变，模糊一个平滑渐变，结果几乎和没模糊一样
- 每块 `backdrop-filter` 都是一个独立合成层，滚动时要重新糊一遍。数据页一次屏里有七八块，滚动帧率会被它拖垮

真正需要模糊的只有「底下有内容在动」的面。WXSS 不保证支持 `backdrop-filter`，老基础库上这条声明会被直接丢掉 —— 所以每块玻璃面都自带半透明底色 + 顶边高光 + 多层阴影，**层次靠阴影兜底，不靠模糊兜底**。

### 材质重量编码层级

浅色半透明叠在浅色半透明上，可读性会塌。一屏之内：玻璃卡之下不再放玻璃卡；交互元素（分段控件的选中块）用更实的面（`$fish-glass-strong`）把自己托起来。

### 面要「materialize」，不要只淡入

一块面入场时应该读作「一层浮起来的材质到了」，而不是「图片加载出来了」。做法是位移 + 缩放 + 淡入一起（`fish-enter`），不是单独的 opacity。

### 唯一那块有颜色的面：光晕的位置定死了谁压在哪

当前天气卡是全项目唯一一张**带天气色**的面。它的构造是两团径向光晕压在一张白底上：
左上那团托着大温度，右上那团托着天气图标。

这两个位置不是排版偏好，是约束：

- 左上光晕要够亮 —— 上面压着 200rpx 的黑色温度数字；
- 右上光晕上面压着图标字形 —— **图标色要跟这团光晕分得开**，
  否则字形埋进同一片色里，等于没画图标。

所以改一组的颜色不是只改那两个光晕：**图标色要跟着一起改**
（浅青的图标压在青晕上就白画了，深晕上的图标要换成白字）。

十组之间靠**色相**分辨（云偏灰、雨偏蓝、雪偏青、尘偏土黄、冷偏紫），
不靠堆饱和度 —— 堆上去十组挤成一团彩虹，反而认不出是哪一组。
各组的色值在 `src/components/CurrentWeather/CurrentWeather.vue`，
码 → 组的映射在 `src/utils/weather.ts`（见 `docs/architecture.md`「天气码归组」）。

## 排版

```scss
@include fish-type(headline); // 分区标题
@include fish-type(body); // 正文
@include fish-type(caption2); // 落款
```

字阶是一组**不可拆**的决策：字号 + 字重 + 字距 + 行高。拆成四个变量之后每个组件都会各写各的，早晚错配。所以用 mixin：拼错一级会在编译期 `@error`，不会悄悄降级成一段没有字距的裸字号。

可选级别：`large-title` `title1` `title2` `title3` `headline` `body` `callout` `subhead` `footnote` `caption` `caption2`。

### 光学配比：字距与行高都随字号反向

这不是风格偏好，是字形本身的物理。大字字心距显得松，要收紧；小字字心距显得挤，要放开。**固定一个 `letter-spacing` 一定会在某一级翻车** —— 这正是「Material 味」的来源。

| 级别                     | 字号           | 字距             | 行高        |
| ------------------------ | -------------- | ---------------- | ----------- |
| large-title              | 34pt           | -0.022em         | 1.15        |
| title1 / title2 / title3 | 28 / 22 / 20pt | -0.02 → -0.016em | 1.2 → 1.3   |
| headline / body          | 17pt           | -0.012em         | 1.35 / 1.45 |
| callout / subhead        | 16 / 15pt      | -0.01 / -0.008em | 1.45 / 1.4  |
| footnote / caption       | 13 / 12pt      | 0                | 1.35 / 1.3  |
| caption2                 | 11pt           | **+0.006em**     | 1.3         |

字距在 `caption2` 转正 —— 这是整套字阶里**唯一**需要放开的地方。

### 只给文字用

图标字形（和风天气图标、★、✕）不要套字阶：字形没有排版语义，套上去会把行高顶到 1.25，在字形下面多留一截空白，把整行格子往下坠；字重和字距加在字形上更是无效代码。字形只写 `font-size` + `line-height: 1`。

### 例外：两种，都要写明理由

**图标字形**（上一节）与**超出字阶的大数字**是仅有的两处例外。

- 首屏的钓鱼指数 152rpx（76pt）、当前天气卡的大温度 200rpx（100pt）——
  都比 `large-title` 大。理由分别是「这一屏的主角」与「这张卡是参考图的复刻」，
  两处都在组件里直写并写明了理由，不靠这条文档兜着。
- 当前天气卡更进一步：整张卡（温度 / 度数符号 / 地点 / 现象 / 高低温）
  都在参考图自己的那一套字号上，不套字阶 ——
  局部套、局部不套才是四不像。

### 没有 Dynamic Type

小程序端系统字号设置不会缩放 WXSS 字号，所以字阶是固定的 rpx。两个后果：别用 viewport 单位写字号（换机型时两级字号的比例会漂）；也别指望用户调大系统字号后布局还成立 —— 用 `rpx` 固定留白，行高给足。

### 自检

- 每段文字都能说出用的是哪一级
- 没有两处写死同一个字号
- 没有裸 `font-size` 出现在正文文本上（字形除外）

## 反馈

反馈有四类，位置和强度都不一样：

| 类型     | 什么时候       | 落在哪                                        |
| -------- | -------------- | --------------------------------------------- |
| **状态** | 正在做，还要等 | 骨架屏 + 流光（`fish-flow`）                  |
| **完成** | 成了           | 结果本身（改数字/换状态），不是弹一个「成功」 |
| **警告** | 即将出问题     | 徽标、等级词（淡底深字）                      |
| **错误** | 已经错了       | 表单内联，贴着出错的字段                      |

**校验要就地，不要等提交。** 用户填完一整张表才被告知哪个字段错了，等于让人重填一遍。

### 骨架屏摆的是什么

状态反馈用骨架屏，而骨架屏摆的是**这张卡最终的样子**，不是一张通用的骨架卡。
`SkeletonCard` 是列表卡的形状（标题行 + 数值块 + 三列），摆在一张方卡上跟最终形状
对不上 —— 数据到了要换一次版，版一换位置就跳。理由同 `VerdictOverview` 的加载态注释。

四条：

- **照真实内容的行盒摆，不是字面高度。** 占位比真实内容矮一截（或高一截），
  数据到了版式一换，下面的东西就跳一下，那一跳读起来就是「页面散架了」。
- **后来才出现的东西也要先占位。** 标题是数据到了才冒出来的：标题晚来一步，
  底下那几行整体往下挪，骨架摆得再准也救不了。
- **空态不是加载态。** 还在取的时候说「暂无」等于说假话 —— 加载判定要覆盖取数的
  **每一段**（定位也算，见 `docs/architecture.md`）。
- **同一个页面里所有加载态同一档呼吸。** 底色 `$fish-surface`、幅度 0.35、时长 1.8s，
  否则一屏里两种加载态一深一浅，像两套组件。

### 按下即反馈

iOS 的按钮是**手指落下就开始缩**，抬手才回弹 —— 等 click 再反应就是「假」的。mp-weixin 的 `:active` 正好在 touchstart 触发，能做到同一件事。

```scss
@include fish-press; // 通用：缩 0.96
@include fish-press-dim; // 分段控件 / 选项组：变暗不缩小
```

按下 100ms、回弹 260ms：靠两条 transition 的时长差实现 —— `:active` 上的 transition 决定「进入按下」的时长，基态上的决定「抬手回弹」的时长。**两处必须都写**，只写一条按下和回弹就一样快，手感立刻变塑料。

`fish-press-dim` 不是备选，是 segmented control 的正确行为：缩小会让整排的选中块位置跳一下，读起来像换了一项。

### 反馈要在交互过程中持续

拖拽、滑块、抽屉这类交互，进度反馈要**跟着手指走**，不是手势结束才给结果。数据页的骨架换实数据属于「状态」，浮层拖拽属于「过程中的进度」—— 后者必须 1:1。

### 触觉

`uni.vibrateShort` 在小程序端可用，本项目**目前一次没用**。提交成功、吸附落位这类「有物理结果」的时刻值得考虑，但只用在真正有意义的地方 —— 多处震动会训练用户忽略它。要加就加在少数几个点子上，不要给每个按钮都加。

### 自检

- 每个可点元素在手指落下那一帧都有反应
- 输入路径上没有多余的 debounce
- 错误提示贴着出错的字段

## 动效

### 曲线即弹簧

iOS 的弹簧用两个参数描述：阻尼比（damping）控制过冲，响应时间（response）控制到位速度。小程序逻辑层没有弹簧引擎，所以**只能近似成 cubic-bezier**：

| 令牌             | 对应的弹簧                                              | 用在哪           |
| ---------------- | ------------------------------------------------------- | ---------------- |
| `$fish-spring`   | 临界阻尼（damping 1.0 / response 0.35），末端减速不回头 | 「跟手之后落位」 |
| `$fish-ease-out` | 呈现曲线（阻尼比略低于 1）                              | 入场、展开       |
| `$fish-ease-in`  | 退场                                                    | 收起、关闭       |

**不要无缘无故地加过冲。** iOS 也只在手势本身带了惯性时才给阻尼不足 —— 过冲用在单纯淡入的菜单上像 bug，用在被甩出去的卡片上才像弹性。

### 时长是一套约定

| 令牌              | 值    | 用在哪                             |
| ----------------- | ----- | ---------------------------------- |
| `$fish-dur-fast`  | 100ms | 按下                               |
| `$fish-dur-cross` | 160ms | **同一位置**换一组内容（交叉淡入） |
| `$fish-dur-press` | 260ms | 抬手回弹                           |
| `$fish-dur-base`  | 500ms | 状态切换、入场落位                 |
| `$fish-dur-sheet` | 600ms | 浮层呈现（面板滑入落定）           |
| `$fish-dur-slow`  | 800ms | 内容落位、头图显形                 |

回弹单独一档，不跟 base 走：base 是「内容落位」的时长，拿来当回弹太长 —— 手指已经离开屏幕了，界面还在慢慢缩回去，读作卡顿。交叉淡入也比 base 短：它的场景只有一个，就是内容在**同一位置**上换一组值，位置不动、只是两组文字互相让位，拖久了就变成两行字叠着闪烁。

### 落位不是表演

```scss
@include fish-enter($delay); // 内容落位
```

只动 `transform` 和 `opacity` —— 这两条在小程序里走合成，不触发布局重排。换成 `top` / `height`，一屏四个分区一起动时每个兄弟节点都要跟着重排一次，掉帧几乎全出在这里。

幅度刻意压得很小：`$fish-enter-y` 是 40rpx（20pt）、缩放 0.95 → 1，配 `$fish-dur-slow`（800ms）读作「本来就在这」。幅度再大就读作「飞进来了」，注意力被动画抢走，反而比不做更难读。

浮层里的内容另有一档：`fish-enter-sheet`（`$fish-enter-sheet-y` = 16rpx / 8pt，不缩放）。幅度更小是因为面板本身已经在滑 —— 内容再大幅上移就是两层位移叠在一起，读作抖。缩放也省掉：面板末尾自己带一点缩放过冲，里面再来一层，文字会被放大缩小地重新光栅化一遍。

逐项延迟用 `enterDelay(index)`（`@/utils/motion`），步长 60ms、**第 9 项封顶**。逐时预报 24 项不封顶的话，最后一项要等 1.44s —— 那已经不是入场动画，是加载动画：用户等的是内容，不是等动画。

### 入场要能重播

CSS 动画同名跑完就是跑完了：二次进入这一页，它停在终态，不会自己再播一遍。重播只有一个办法 —— **把 `animation-name` 摘掉再挂回**，用行内样式做（`enterStyle(index, show)`，`@/utils/motion`）。

`show` 为 false 时写 `animation-name: none`，动画没了，元素停在自己「先不在」的状态（`opacity: 0` 写在 `fish-enter` mixin 里）。这样摘动画的那一下屏幕上不会先亮一下终态再淡入；翻回 true 时名字换回去，动画从头跑。

开关由页面持有（数据页的 `showAnim`，`onPageShow` 里先摘后挂），**组件自己管不了自己的重播**：概览那一屏的动画在组件内部，父级摘不掉，只能由页面翻开关传进来。

两条跟着来的约束：

- 动画归组件管，页面只给一个布尔。概览组件的 `showAnim` prop **默认 true** —— 初始状态在类上，动画一旦被摘掉又没人挂回去，内容就是永久隐形。默认值就是这条的兜底。
- 带 `fish-enter` 的元素，行内 `animation-name` 必须由同一个开关驱动。别一半走类、一半走行内：类那条动画跑完就停在终态，和行内那条对不上号。

### 数字滚动

有一类动效 CSS 表达不了：**文本内容本身在变**（"0" 滚成 "72"）。这不是样式变化，是数据变化 —— CSS 只能改 `transform` / `opacity`，改不了字面。所以数字滚动必然走逻辑层，是全项目唯一一处 JS 驱动的动效（`utils/motion.ts` 的 `createCountUp`）。

既然躲不掉 JS，就得把跨线开销压到最小：**每改一次值就是一次 `setData`**。控制器只在整数真的变了的时候才写一次，0→100 全程最多 101 次。

三条时序约定：

- **数字跟它那一行同时开始、同时落定。** 分数是入场序列里的第 1 项，数字就用同一条延迟（`enterDelayMs`）起滚，时长取 `$fish-dur-slow` 那一档（800ms）。数字滚完的那一刻，行也刚好坐到位 —— 读起来是「一次落位」，不是两件事各演各的。
- **重播时数字回到 0 重新数。** 摘掉入场动画时数字跟着归零：数字停在旧值上、只有别的东西在动，读起来是「卡住了」。
- **刷新时从当前值补间，不从 0 重数。** 刷新回来 62 分，数字从 60 走到 62 —— 那一下「几乎没动」本身就是「刷新成功」的信息；从 0 重数会把这条信息抹掉。

数字那一行还开着 `font-variant-numeric: tabular-nums`：滚动时位数不变（0→100 最多三位），等宽数字才不会让整行宽度一跳一跳。

### 动画定义放哪

- **变量和 mixin** → `src/styles/tokens/`（要靠它拿值）
- **`@keyframes` 和 `@property`** → `App.vue` 的 `<style>`（全局一份）

令牌那一层每个组件各 `@use` 一次，写在那里的 `@keyframes` 会跟着复制十几遍同一个动画定义。

流光的 `--fish-flow-angle` 必须是注册过的 `@property <angle>`，否则关键帧对它只能离散插值，在 0deg 和 360deg 之间硬跳一次 —— 而这两端的 conic 渐变完全相同，等于流光根本不动，只是每 3 秒闪一下。

### 三个平台坑（完整版见 `docs/mp-weixin-platform.md`）

1. **组件宿主节点不吃动画。** 自定义组件在页面的 WXML 里就是一个标签，页面样式能匹配到它，但挂在标签上的 `animation` 不动。要动的是组件外面那一层 —— 在页面里给组件套一个普通 `<view>`，动画挂在这个 view 上。因为入场动画的初始状态（`opacity: 0`）写在类上，宿主节点会拿到 `opacity: 0` 而动画又不动，结果是**内容永久消失**。
2. **`animation-fill-mode` 用 `both`。** 入场带序号延迟，延迟期间元素要停在 `opacity: 0`。用 `none` 的话，那几百毫秒里元素是完全可见的，然后突然又从 0 开始淡入 —— 闪一下再重来，比跳帧更难看。
3. **不要用 `uni.createAnimation`。** 它不支持 cubic-bezier、要跨线传输、`export()` 每次清空队列。本项目动效一律走 CSS transition / `@keyframes`，由渲染引擎在视图层本地跑完，运行时零 JS 开销。

### 降级开关在编译期

`src/styles/tokens/_motion.scss` 的 `$fish-motion` 置 false 后，`fish-enter` 一段不生成，界面直接以终态呈现。关键帧也跟着关（`App.vue` 里同一个开关），否则数据页用行内 `animation-name` 重播入场时照样能引用到它，降级就只剩下一半。

WXSS 没有开放 `prefers-reduced-motion`，逻辑层也没有对应的系统 API —— 写一条不生效的媒体查询进去只会造成「已经处理过了」的错觉。

## 手势与浮层

浮层统一用 `SnapSheet` 容器。当前五处共用同一个，才谈得上「同一个手势、同一种落位」：

| 浮层                           | 宿主页                       |
| ------------------------------ | ---------------------------- |
| 钓鱼反馈 `FishingFeedbackForm` | 数据页                       |
| AI 建议 `FishingAnalysisSheet` | 数据页                       |
| 资料编辑 `ProfileSheet`        | 我的页                       |
| 钓点分享 `SpotShareSheet`      | 钓点详情页                   |
| 协议文档抽屉                   | 关于页（直接用 `SnapSheet`） |

`SnapSheet` 只提供容器，标题区归页面。钓点详情页本身**不是**抽屉 —— 它是一整页，头图压顶、底栏浮在内容上，不要为了「统一」把它塞回浮层。

### 1:1 跟手

手指走多少，面走多少。拖拽期间必须关掉 CSS transition（`dragging` 时 `transition: none`），否则面会追着手指跑，差值就是「粘滞感」。

### 手势归属

拖拽是**把手区独占**的手势。四个事件全用 `catch`：一旦冒泡出去，背后的页面会跟着滚、背后的地图会跟着动。

面板上**只挂 `touchmove`、不碰 `touchstart`** —— `catchtouchstart` 会把 scroll-view 的手势一起抢走，滚动就废了。`catch` 只断冒泡，不取消区域滚动。

### 松手判定：先看方向，再看量

位置阈值 80px 与速度阈值 500px/s，二者取其一即触发。**方向比距离重要** —— 手指往下甩哪怕只走了 20px，意图也是「收起」，不是「没走够」。

吸附是「落位」不是「甩过去」，所以用临界阻尼（`$fish-spring`），不过冲：档位切换加了过冲会读成弹了一下。

### 空间一致性

**从哪来，就回哪去。** 面板从底部下方滑上来，也原路退回底部（`translateY(100%)`，锚的是面板自身高度，所以矮面板不会只滑一半露底）。遮罩与面板**同时**退场，各 260ms —— 背景在面板滑落的同时暗回去，不是等面板走了才撤遮罩。

入场走 `$fish-ease-out`（呈现），退场走 `$fish-ease-in`（退场）—— 一来一回是镜像关系，不是两套曲线。入场时遮罩 500ms 淡入、面板 600ms 滑入：面板比背景晚到位，一层一层压上来，读起来是「拿起来」而不是「淡入」。

### 入场是三段，不是两条曲线

面板入场写成「滑上来 → 越过一点 → 落定」三段关键帧（`snap-panel-in`），不是一个 `from/to`：

- **行程**（0 → 70%）：`translateY(100%) → 0`，配 `$fish-ease-out`。
- **越过**（70%）：`scale` 到 1.012，比落位大一点点。
- **落定**（70% → 100%）：缩回 1，之间再经过一次 0.997 的小回落 —— 阻尼衰减，读作弹簧。

**为什么不写成一条带过冲的 cubic-bezier**：过冲是按比例作用于所有属性的，而面板的位移按**自身高度**算、缩放只有 2%。同一个过冲比例会让面板离地 1%，屏幕底下露出一条缝。所以行程和回摆必须分开写。

**过冲挂在缩放上，不挂在位移上**：`transform-origin: bottom center` 把底边钉在屏幕上，越过的是上沿 —— 读作「它被顶过头了一点」，不是「它飘了一下」。iOS 的呈现也是这个形状：面板被顶起来，落定时稍微回一点。

这一档过冲是**面板呈现**才有的，跟「不要无缘无故地加过冲」不冲突：那条劝退的是纯淡入的菜单。面板是被拿起来的物体，末端越过落点再落定就是它的物理。抬手吸附那种「落位」仍然是临界阻尼（`$fish-spring`），不过冲。

### 面板里还要再落一层

面板往里走的同时，里面的内容逐块落位（`fish-enter-sheet`，延迟 240ms 起）：头部 → 正文 → 底部动作，各晚 60ms。延迟不能更早 —— 面板还在路上时内容就落完，读起来像面板是空的。

两层是分开的：面板是**位移**（它从屏幕外来），内容是**落位**（它在这个面板里就位）。合成一层的话，读者只看到「一大块东西滑进来」，分不出浮层是拿起来的还是内容在加载。

幅度比页面内的小（16rpx vs 40rpx）：面板本身在动，内容再大幅上移就是两层位移叠在一起。

### 先量后动

面板的高度是量出来的（`SelectorQuery` 量头部、正文、底部动作区），量的时候入场动画必须**按住不动**（`--preparing`）：带着缩放量，量到的是变形后的盒子，滚动区会凭空短一截；带着位移量同理。

所以顺序是：面板挂上去（透明）→ 量 → 放手动画 → 面板滑进来。量高回不来时面板会一直藏着，所以有一道 400ms 兜底：宁可先用估值高度出场，也不能让浮层打不开。

## 页面骨架

三类页面，共用同一套材质与字阶，但骨架不同：

| 页面                       | 骨架                         |
| -------------------------- | ---------------------------- |
| 数据、我的、关于、我的钓点 | 环境色底 + 分区版式 + 玻璃卡 |
| 钓点创建、钓点编辑         | 环境色底 + 表单流            |
| 钓点详情                   | 照片压顶 + 底栏浮在内容上    |

数据、我的、关于是同一个 app 的三面，共用同一套骨架：

- 环境色底 → `<PageBackdrop />`（固定在视口上，不随内容滚走）
- 分区版式 → `_layout.scss` 的 `fish-section` / `fish-eyebrow` / `fish-foot`
- 玻璃卡 → `_card.scss` 的 `fish-card`（外壳 + 标题行 + 标题 + 元信息）

**新页面照抄这几页的骨架，不要另起一套。** 各写一份的话，改一次色要记得改两处，漏一处就出现「一页冷、一页暖」这种没法一眼说清、但一眼能看出的怪。

环境色底**不放在全局 `page` 底色上** —— 全局底色还得给 tabBar 切换时露出的那一帧兜底，也给钓点页的原生地图边缘兜底；一旦全局换成渐变，地图边缘会跟着染上颜色。渐层只属于「有内容的页面」，所以它是一个可以按页放下的元素。

### 首屏定高

数据页的第一屏是**概览**，它自己占满一屏：高度取 `windowHeight`（px，不含 tabBar），内容从 `navBarBottom` 往下排。

- **不用 `100vh`** —— 100vh 把原生 tabBar 的高度也算进去了，页面会多出一截能拖出去的范围（见 `useViewport` 的注释）。
- **定高之后，下面第一张卡正好落在折叠线下面** —— 用户往下滑，第一眼看到的是完整的「天气」分区，而不是半张卡。
- 概览区只回答一个问题（今天能不能钓）。成因、逐时、潮汐这些是「为什么」和「细节」，压在它下面，别跟结论抢第一屏。
- 定高留出的空白是**算出来的**，不是没内容。所以底部要有一行「往下看」的提示，否则那片空白会被读成「没加载出来」。

高度由概览组件自己绑（它就是第一屏，高度就是这一屏的高度）；页面只管它下面那些分区怎么排。

### 钓点详情：一屏

钓点详情页的第一屏要回答的是「今天值不值得去」，所以它的骨架是**一屏定内容**，
不是**一屏定高度**（它照常往下滚）。

- **头图 280pt**（`SPOT_HERO_HEIGHT_RPX = 560`）。372pt 的头图把第一屏全吃掉了 ——
  用户要滚一下才看得到「能不能钓」。收到 280pt 之后，头图、名字、结论、四因子落在同一屏里。
- **描述限两行**，多出来的收进「展开」。这一页是给人判断要不要去的，
  一段三百字的描述会把首屏撑走，而首屏里真正该被看见的是「今天能不能钓」。
- **钓点信息压成 2×2**（标签在上、值在下）。四个字段各占一行的话，它自己就是一屏。
- **结论前置**：等级词（22pt，语义色）+ 一句话结论占主位，
  气压 / 风力 / 气温 / 潮汐四格退成 20pt 的支撑位 —— 数字变大不增加信息，只增加噪音。

**等级词与配色跟数据页同一套**（`utils/weather` 的 `levelTone`）：
同一个 level 在两个页面上必须是同一个颜色。两处各配一套的话，
用户会以为这是两个不同的指标 —— 而同一个词出现两种颜色，只会被读成「有一个是错的」。

**分区标题统一 eyebrow**（12pt / 600 / 字距放开 / tertiaryLabel）：
今日钓况、钓点信息、现场照片三段同一档声音。
一个 17pt 墨色、一个 12pt eyebrow 混着来，这一页会读成三页拼起来的。

**导航栏的两态是分开的**：`solid` 管图标颜色，`material` 管那条磨砂带。
没有照片时头图是浅色插画，白箭头压在上面读不出来 —— 这时**从头**就用实底图标；
但磨砂带不跟着出来：它的作用是托住滚过去的内容，底下什么都没有时铺一块半透明白面，
只是把插画切开。

**描述的钳制怎么量**：同一个盒子量两次 —— 一次钳着（两行高）、一次放开（自然高度），
自然高度更大才说明文字被切掉了。不要拿「文本节点的高度」去比：
文本节点在钳制盒子里被裁着，各渲染层给的高度口径不一致，
拿它比会得出「永远不溢出」的错误结论。量不出来时整段显示、不给「展开」——
宁可多显示几行，也不能把文字切掉又没给开的路。

**钓况那一块自己轮换三种状态**：加载中摆骨架、取不到摆「重新获取」、有数据摆结论。
整块不出现的话，页面会在名字卡和钓点信息之间空掉一块，用户以为没有钓况。
骨架照着真实内容的**行盒**摆，不是字面高度 —— 占位比真实内容矮一截的话，
数据到了版式一换，下面的东西会往上跳一下，那一跳读起来就是「页面散架了」。
失败文案要说明「只是这一块没取到」（"钓况暂时取不到，钓点信息不受影响。"），
说成「加载失败」会让用户以为整页都废了。

### 我的页：身份 + 两组出口

这一页答两件事：**我是谁**，以及**我要往哪儿走、我要做什么**。
「这是什么」搬去了关于页 —— 一个页面同时讲身份和讲应用，两件事互相稀释。

骨架是三块：**身份卡** + **入口组** + **动作组**，最后一行是破坏性操作。

**眉标只在「组里有好几行，且组名不显然」时才出现。**
一组的行彼此无关时（「分享渔碌给朋友」和「联系客服」），得有个名字把这组收住；
只有一行时不需要 —— 行标题自己就说清了，章节标题反而比它下面那一行还重，
读者要停下来想「这一段叫什么」。
原来这一页给三个分区各配了一个眉标，其中两段各只有**一行**，是纯粹的版式浪费。

**入口与动作靠箭头区分，不靠图标。**
带展开箭头的是「点进去是另一页」，不带的是「点下去发生的事就在微信那边」。
两组各占一张卡：上面那组点进去都是另一页，混进来用户会以为这两行也是，
点下去却是微信自己的面板，反差很大。

**行的解剖**（`components/MineRow`）：行首图标 + 行标题 + 右侧载荷 + 展开箭头。

- **行首图标统一烤成蓝色**。一行里图标与文字不同色，就有了两个焦点。
- **载荷**是这一行的内容，不是标题：「我的钓点」不是一条空链接，
  它带着「12 条」与一枚「2 条待审核」的徽标。
- **徽标淡底 + 深字**，跟「我的钓点」页里的状态徽标同一套 ——
  同一个状态在两个页面上必须是同一种颜色，否则用户会以为有一个是错的。

**破坏性操作独居一格。**
「退出登录」原来跟「编辑资料」是同权并排的两个按钮，还放在全页最显眼的位置。
退出是不可逆的，该被看见，但不该被当成一个普通入口 ——
所以它不套在卡里，独居一行、居中、红字。卡里的行是「往哪儿走」，
它不是。

**数量取不到就不显示。**
显示「0 条」跟「真的没提交过钓点」分不清，而这一页不该替用户下「你没有钓点」
这个结论 —— 取不到就当没数，点进去「我的钓点」那一页会给出真正的答案。

**可点的东西要长成可点的样子。**
头像是 `chooseAvatar` 按钮，但一张头像长得就是一张照片 ——
没有右下角那枚相机角标，没人知道点它能换头像。

### 分区

```vue
<view class="sect">
  <text class="sect__title" :style="{ animationDelay: enterDelay(0) }">天气</text>

  <!-- 动画挂在外层这个普通 view 上：组件标签（宿主节点）不吃动画 -->
  <view class="sect__card" :style="{ animationDelay: enterDelay(0) }">
    <HourlyWeather />
  </view>
  <view class="sect__card" :style="{ animationDelay: enterDelay(1) }">
    <MetricChart />
  </view>
</view>
```

```scss
.sect {
  @include fish-section;
}
```

三条定死了「页面怎么分块」：分区自己左右缩进 32rpx（留白是页面级的，不留在各张卡里）；分区之间 40rpx（跨段是分组，比同段并列大一档）；同段内两张卡之间 32rpx。

分区用 flex 列而不是块级流：块级流会做外边距合并，两层留白叠在一起时算出来的数不是写下的那个数。

**分区间距由页面给，组件不再自带 margin-top。** 区块之间怎么分开是页面的版式决定，不是各组件自己的事。

**眉标只在「组里有好几张卡，且组名不显然」时才出现。** 卡片自己带标题的时候，眉标只是把卡片标题又说一遍 —— 卡片不带标题的时候（天气详情那张读数表）眉标必须留着，否则那一段就没有名字。

**同段内并排的两张半宽卡共用一个高度。** 左边那张的地点名多换一行，右边就矮一截，一对卡看着像两张各说各话的卡。所以那一行用 stretch 拉伸，两张卡自己 `height: 100%` 填满拉出来的高度（见令牌层 `_layout.scss` 的 `.sect__row`）。

### 落款

```scss
.data__foot {
  @include fish-foot;
}
```

一句话交代出处就完了 —— 它是页面的句号，不该跟上面的内容抢视线。字号压到 caption2、颜色压到 tertiaryLabel。

### 一页一件事

一个页面只回答一个问题。数据页给结论，我的页给身份与出口，关于页给应用 —— 一个页面同时回答两个，两件事互相稀释。

「我的」页多出来的那个「出口」是分享与联系客服：它们是**动作**，点下去发生的事就在微信那边，
不领人去看新的一页。动作跟入口（通往别的页面）分开放，用户点之前就知道会发生什么。

### 一件事只说一遍

**同一件事在一屏里说两次，等于一次都没说。** 读者要自己判断「这两句是不是一回事」，
判断成本比读成本还高 —— 界面看着信息多，其实什么都没多。

判据很简单：**把这一屏的文字念出来，凡是同一个事实出现两次，删到只剩一次。**
不是删句子，是把重复的那一份交给「本来就该说这件事的东西」。

**谁来说，事先分好：**

| 事实             | 归谁说   | 长什么样                         |
| ---------------- | -------- | -------------------------------- |
| 现在什么状态     | 状态控件 | 一枚胶囊 / 一枚徽章，只报状态    |
| 现在能做什么     | 按钮     | 文案就是动词：生成 / 停止 / 重来 |
| 还没发生、占着位 | 占位文案 | 一句**问句**，不是一个操作说明   |

**占位文案不能是操作说明。** 按钮就在屏幕上，写「点击下方按钮获取建议」是把按钮又说了一遍。
写成问句 ——「今天适合几点去？」—— 用户读到的是一个具体的问题，
按下去的理由也就顺着他自己的需求长出来了。

**状态徽章和按钮文案重复时，删徽章。** 「待生成 / 生成中 / 已生成 / 已停止」这排徽章
和按钮上的「生成建议 / 停止 / 重新生成」是同一张表。徽章只在按钮文案**无法表达**状态时才留。

**同一屏只能有一个主角。** 结果裸铺在白底上，就该给它一层浅底托起来 ——
否则它不是「一句回答」，只是「面板里的一段字」。
（这就是「材质分层」那条底线：靠面分层，不靠描边。）

**思考过程收进胶囊，不占结论的位置。** 过程是给想看的人看的，结论是给所有人看的。
过程另起一块分隔线以下的正文，等于逼所有人先读过程。

#### 自检

- 把这一屏的文字通读一遍，标出重复的同一件事 —— 标得出就该删
- 每个可点的元素，问一句「它的文案是不是这个动作的动词」
- 空态问一句「这是不是一个具体的问题，而不是一句操作说明」
- 结果区问一句「它有没有被一层面托起来，还是裸铺在底色上」

### 路径寻找

每个页面都要能回答四个问题：**我在哪？我能去哪？这里有什么？我怎么出去？** 不把人困住：浮层能拖能关，遮罩可点，空态要给出下一步。

## 图标

图标是 `scripts/gen-icons.mjs` 从 lucide-static 生成的数据 URI，`src/constants/icons.ts` 是它的生成物。

小程序端不能把 `<svg>` 内联进 WXML（渲染层不认），能落地的只有 `<image src="data:image/svg+xml;base64,…">`。这条路上的 SVG 是当图片渲染的，**拿不到页面的 CSS 上下文，`currentColor` 不继承** —— 所以颜色必须在生成时烤死。这也是为什么 `gen-icons.mjs` 里那套色板要手工跟 `_color.scss` 对齐：CSS 变量传不进 `<image>`。

清单刻意压着不加 —— 图标一多，页面就从「读数据」滑向「看图标」。

## 单位

- **rpx** 是设计稿尺寸（1pt = 2rpx），**px** 是运行时量出来的尺寸（`useViewport` / `useNavMetrics`）

两者相加先过 `uni.upx2px()`，换算细节见 `docs/mp-weixin-platform.md`。

## 现状缺口与待办

以下几条是当前实现与 Apple 原则之间的差距，都**如实记录**在此，不假装已经做到。按影响从大到小排。

### 1. 浮层退场期间不接手势

**现状**：`SnapSheet` 在 `closing` 为 true 时直接 `return`，退场动画播完才摘节点。

**差在哪**：违反了「过渡期间不锁输入」。用户退场时想抓住把手拉回来，260ms 内完全没有反应。

**怎么改**：退场做成可打断 —— 抓到把手就把退场类摘掉、回到拖拽态。代价是退场定时器与节点生命周期要重排（现在靠 `setTimeout` 到点摘节点）。

### 2. 拖拽到边界是硬夹

**现状**：`heightPx` 被 `Math.min` / `Math.max` 夹在上下限内。

**差在哪**：Apple 的软边界是**渐进阻力**（橡皮筋），越拖越沉，最后才停。硬夹读作「撞到墙了」。

**怎么改**：超界时按比例衰减跟随量 —— `跟随量 = 超界量 × 0.55 × 视口尺寸 / (视口尺寸 + 0.55 × 超界量)`（`dimension` 取面板可拖动行程）。

### 3. 松手不做动量投影

**现状**：只有位置阈值与速度阈值二选一，快甩时落到相邻档。

**差在哪**：Apple 是用速度**投影**出落点，再吸附到投影落点最近的档位。快甩时按相邻档吸附会「差一档」。

**怎么改**：`project(v) = (v / 1000) × 0.998 / (1 − 0.998)`，取 `当前位置 + 投影`，再找最近的档。

### 4. 抬手不交接速度

**现状**：松手后高度交给 CSS transition（280ms），起点是松手那一刻的位置，不带手指速度。

**差在哪**：落位的起点速度是 0，而不是手指离开时的速度 —— 拖拽与落位之间有一道**接缝**。

**怎么改**：CSS transition 接不了速度。真要接，得走 WXS 或 `this.animate` 的视图层路径（见 `docs/mp-weixin-platform.md` 的「WXS：目前用不上」）。

### 5. 没有触觉反馈

**现状**：`uni.vibrateShort` 一次未用。

**怎么改**：提交成功、吸附落位各给一次轻震动即可，别处不加。

### 6. 只有临界阻尼一种手感

**现状**：三条曲线里没有过冲的一档。

**差在哪**：被甩出去的元素落位时没有回弹。

**怎么改**：加一条低阻尼曲线，**只用在有惯性手势之后**，不用在单纯淡入上。

### 7. 拖拽全在逻辑层

**现状**：拖拽每一帧都改 `heightPx`，每次都是一次跨线 setData（传的是高度这一个数字，不是样式表）。

**差在哪**：不算错，但连续手势走逻辑层始终比视图层本地慢一拍。

**怎么改**：真要更跟手，迁到 WXS。这条是投入产出比最低的一条，先不做。

### 8. 降级开关盖不住浮层自己的关键帧

**现状**：`$fish-motion` 置 false 之后，页面级的入场动画不生成，但 `SnapSheet` 的面板关键帧（`snap-panel-in` / `snap-panel-out`）是组件内定义的，没有跟着关 —— 浮层照样滑。

**差在哪**：关掉动效的开关应该是全局的。现在的效果是「页面不演了，浮层还在演」。

**怎么改**：把这两段关键帧和退场时长一起挂到 `$fish-motion` 下面。退场那 260ms 的定时器也要跟着 —— 关键帧没了但节点还按旧时长等着摘掉，中间会有一段面板停在原地。

### 9. 降级开关盖不住数字滚动

**现状**：概览那一屏的分数是滚出来的（"0" 滚成 "72"）。字面在变，CSS 改不了，所以它是全项目唯一一处 JS 驱动的动效（`utils/motion.ts` 的 `createCountUp`）。`$fish-motion` 置 false 之后，页面不演了，数字照滚。

**差在哪**：同第 8 条 —— 降级开关应该是全局的。现在的效果是「页面不演了，数字还在演」。

**怎么改**：把这个开关搬到一份 SCSS 与 JS 都读得到的地方（`src/config` 下的常量 + 构建时注入），两边都从它派生。代价是一轮构建链改造，先不做。
